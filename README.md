**생활 습관 기반 뇌 영역별 인지 부하 추정·시각화 웹 프로토타입**

**1인 개발 프로젝트 (1인 팀 / 단독 개발)** · 설계프로젝트 · 의료 IT (건강 정보 시각화, 번아웃 예방)

> ⚠️ **안내:** 본 프로젝트는 교육용 개념 증명(Proof of Concept)입니다. 진단·치료 도구가 아니며, 모델의 가중치는 문헌이 보여 주는 영향의 **방향**에 근거한 **가정값**입니다. 실제 사용자 데이터로 검증하지 않았습니다.

## 2. 문제 정의 (Problem Statement)

### 2.1 문제
대학생과 직장인은 수면 부족, 장시간 작업, 화면 사용으로 인지 피로를 겪는다. 그러나 피로를 하나의 주관적 숫자("얼마나 피곤한가")로만 보면 **어떤 습관이 어떤 기능에 부담을 주는지** 알기 어렵고, 번아웃은 서서히 진행되어 뒤늦게 인식되는 경우가 많다.

### 2.2 문제의 근거와 실제성
본 저장소는 새로운 통계 수치를 주장하지 않으며, 아래 문헌이 보여 주는 **영향의 방향성**만 근거로 삼는다.

- 만성적인 수면 제한은 주의력 결핍을 누적시킨다 (Van Dongen et al., 2003).
- 수면 부족은 의사결정 능력을 떨어뜨린다 (Harrison & Horne, 2000).
- 장시간 과제 수행은 정신적 피로를 유발한다 (Boksem & Tops, 2008).
- 화면 작업은 시각 피로(컴퓨터 시각 증후군)와 관련된다 (Rosenfield, 2011).
- 번아웃은 세계보건기구(WHO) ICD-11에서 질병이 아닌 '직업 관련 현상(occupational phenomenon)'으로 분류된다 (WHO, 2019).

### 2.3 해결 방향
생활 습관 5가지를 입력하면, 뇌의 4개 영역(전전두엽·두정엽·측두엽·후두엽)이 각각 얼마나 부담을 받는지 **추정**하여 색과 보고서로 보여 준다. 목적은 진단이 아니라 **자기 인식과 예방적 행동(휴식, 수면 조정)의 유도**이다.

## 3. 목표와 차별점

### 3.1 목표
| ID | 목표 |
|---|---|
| G1 | 생활 습관이 인지 부하에 미치는 영향을 영역별로 시각화한다 |
| G2 | 계산 과정을 모두 공개하는 **설명 가능한(투명한)** 모델을 만든다 |
| G3 | 수면 부족이 날마다 누적되는 효과(수면 부채)를 반영한다 |
| G4 | 색에만 의존하지 않는 접근성(아이콘·문구)을 제공한다 |
| G5 | 모델의 한계를 숨기지 않고 문서화하고, 검증 계획까지 제시한다 |

### 3.2 특징 (기존 서비스와의 비교 우위는 조사하지 않았으며 주장하지 않음)
1. 입력값을 **원인 변수**(수면, 연속 작업, 작업 시간, 화면 시간, 과제 난이도)로 한정하고, 피로와 오류율 같은 **결과 변수**는 입력에서 제외하여 이중 계산을 피했다.
2. 영역별 가중치 표와 수식을 화면과 문서에 모두 공개한다.
3. 시그모이드 변환으로 "적은 부하에서는 보상, 중간 부하에서 급격한 저하, 높은 부하에서 포화"라는 비선형성을 표현한다.
4. 주간 수면 부채 누적과, 부채가 없었을 경우의 지수를 나란히 비교한다.

## 4. 모델 로직

> 본 모델은 데이터로 학습하지 않는다. 연구 문헌이 보여 주는 방향(수면 부족 → 주의력·기억 저하 등)을 바탕으로 **개발자가 정한 가중치**를 적용하는 규칙 기반 모델이다.

### 4.1 처리 흐름
```
입력 5종 → 수면 부채 계산 → 0~1 정규화 → 영역별 가중합 L → 시그모이드 → 영역 점수(0~100%)
        → 상태 분류(색·아이콘) → 종합 지수 → 규칙 기반 분석 보고서
```

### 4.2 수식
1. **수면 부채** (일 단위, 시간): `D_n = max(0, 0.7 · D_(n-1) + (8 − 수면_n))`
2. **정규화**: `s = min(D/6, 1)`, `b = min(연속작업(분)/120, 1)`, `h = min(작업시간/10, 1)`, `c = 과제난이도/10`, `r = min(화면시간/10, 1)`
3. **영역별 가중 부하**: `L = w_s·s + w_b·b + w_h·h + w_c·c + w_r·r` (영역별 가중치의 합 = 1)
4. **시그모이드**: `S(L) = (σ(L) − σ(0)) / (σ(1) − σ(0))`, `σ(x) = 1 / (1 + e^(−k(x − 0.5)))`, `k = 8`
5. **영역 점수**: `Score = round(100 × (1 − S(L)))` (높을수록 좋은 상태)

### 4.3 영역별 가중치 (가정값)
| 영역 | 수면 부채 | 연속 작업 | 작업 시간 | 과제 난이도 | 화면 시간 |
|---|---|---|---|---|---|
| 전전두엽 (집중·의사결정) | 0.30 | 0.20 | 0.15 | 0.30 | 0.05 |
| 두정엽 (주의·감각 통합) | 0.25 | 0.25 | 0.10 | 0.30 | 0.10 |
| 측두엽 (기억·정보 처리) | 0.35 | 0.10 | 0.25 | 0.20 | 0.10 |
| 후두엽 (시각 처리) | 0.10 | 0.10 | 0.15 | 0.10 | 0.55 |

### 4.4 상태 분류
| 점수 | 색 | 아이콘 | 의미 |
|---|---|---|---|
| 70% 초과 | 초록 | ✓ | 최적 상태 |
| 40% 이상 70% 이하 | 노랑 | ! | 중간 정도의 피로 |
| 40% 미만 | 빨강 | × | 심각한 과부하 |

종합 지수는 4개 영역 점수의 평균(반올림)이다.

### 4.5 계산 예시 (단일 일자, 전날 수면 부채 0 가정)
| 시나리오 | 입력 (수면, 연속 작업, 작업 시간, 화면, 난이도) | 전전두엽 | 두정엽 | 측두엽 | 후두엽 | 종합 |
|---|---|---|---|---|---|---|
| 컨디션 좋음 | 8시간, 30분, 3시간, 2시간, 3 | 94 | 93 | 94 | 93 | 94 |
| 평범한 하루 | 7시간, 45분, 7시간, 5시간, 5 | 69 | 69 | 66 | 53 | 64 |
| 과부하 | 4시간, 150분, 12시간, 11시간, 9 | 3 | 3 | 4 | 1 | 3 |

### 4.6 분석 보고서 생성
보고서는 생성형 AI가 아니라 **규칙**으로 만든다. 가장 점수가 낮은 영역을 찾고, 그 영역에서 `가중치 × 정규화값`이 가장 큰 요인을 주요 원인으로 정한 뒤, 요인별로 미리 작성한 권장 문구를 출력한다. 권장 문구는 일반적인 건강 지침을 참고한 예시이며 임상적으로 검증된 처방이 아니다.

## 7. 실행 방법

1. 저장소를 내려받는다: `git clone <저장소 주소>`
2. `index.html`을 웹 브라우저로 연다 (설치·서버 불필요). 최신 Chromium 계열 브라우저에서 개발·확인했으며, 다른 브라우저는 검증하지 않았다.
3. 선택: GitHub Pages를 켜면 URL로 바로 실행할 수 있다 (Settings → Pages → Branch: main).
4. 사용 방법
   - 왼쪽 슬라이더 5개로 하루 습관을 입력한다.
   - 상단 요일 막대에서 날짜를 골라 주간 수면 부채 누적을 확인한다.
   - 뇌 영역이나 오른쪽 목록을 눌러 영역별 설명과 권장 사항을 본다.
   - `데모` 버튼은 세 가지 시나리오를 자동 재생한다. 우측 상단에서 언어(한국어/러시아어)와 테마를 바꾼다.

## 8. 한계와 검증 계획

| 한계 | 설명 |
|---|---|
| 가중치 | 개발자의 가정값이며 데이터로 보정하지 않았다 |
| 모델 형태 | 선형 가중합 + 시그모이드는 단순화이며 실제 관계는 더 복잡하다 |
| 영역 구분 | 인지 기능은 개별 엽이 아니라 분산된 네트워크가 담당한다 |
| 입력 | 사용자가 직접 입력하며 센서와 연동되지 않는다 |
| 정확도 | 측정하지 않았으며 어떤 수치도 주장하지 않는다 |

**검증 계획 (미실시):** 자원자를 대상으로 카롤린스카 졸음 척도(KSS)와 NASA-TLX를 기록하고, 같은 날의 모델 지수와의 상관(예: Spearman)을 분석한다. 결과에 따라 가중치를 회귀로 보정한다. 인간 대상 연구에는 기관생명윤리위원회(IRB) 검토가 필요하다.

## 9. 개발 과정 및 AI 도구 사용 고지

이 프로젝트의 코드와 문서는 생성형 AI(Claude)와 대화하며 작성했다. 개발자는 요구사항과 방향을 제시하고 결과를 검토·선택했으며, AI는 구현과 일부 설계 제안(예: 시그모이드 변환, 입력 변수 재구성)을 담당했다. 자세한 단계별 내용은 [개발일지](docs/개발일지.md)에 있다. 본 과목에서는 생성형 AI의 사용이 허용되며, 위와 같이 사용 사실을 밝힌다.
